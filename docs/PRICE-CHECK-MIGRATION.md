## Source HTTP contract

`app.py::routes` serves GET HTML: `/`, `/bulk`, `/advanced` use `static/index.html`; `/preview/provider` and `/preview/bulk` use that same HTML; `/admin[/]`, `/admin/providers[/new|/{provider_id}]`, `/admin/shops`, `/admin/bulk`, `/admin/logs`, `/admin/cache`, `/admin/security` use `static/admin.html`. Static assets are under `/static`; `/favicon.ico` serves the mark. Unknown `/api/` paths return 404 JSON; other unknown paths serve `static/404.html` (`not_found_page`). Framework HTTP exceptions other than 404 return plain text, including method errors. GET routes also have Starlette's implicit HEAD behavior.

All API paths below are under `/api`. Successful JSON responses default to 200 unless indicated. Ordinary errors use `{detail, errors:[{field,message}], ...extra}` (`api.py::ApiError/json_error`); unexpected exceptions produce 500 `{detail:"internal error"}`. Preserve Persian messages and field paths. Do not expose WordPress's native error shape to the existing JS without an adapter. `_body` accepts empty body as `{}`, rejects malformed JSON or non-object JSON with 400. Unknown/inactive public providers return 404. IDs or technical names resolve through `providers.get_provider`; location lookup additionally accepts display titles case-insensitively.

## Calculation and flow preservation

**Provider configuration:** `records.py::normalise/_params/_fields/_rules/_location_config/normalise_bulk_config` and `providers.py::_build_record`. Stable provider/param/field IDs, names, ordering, visibility, defaults, active state, endpoint, shop ID, logo, timeout, price paths/main key, referral, unit settings, rules and location configuration are functional data. Inputs: text/number/select/list/dict/map; value types str/int/float; kind city/province/money/weight. Validate duplicate names, invalid target references and map output-key collisions. Preserve options and nested row fields. Timeout defaults to 15 seconds; configured bounds are 1–300 seconds (`records.py::_timeout`). Save owned row IDs in place; foreign/duplicate IDs become new rows (`storage.py::save_provider`), preserving ID-based bulk references through rename.

**Single quote:** load active list → schema/reference bindings → collect dynamic form → parse request and run abuse guard → resolve active provider → normalize defaults and typed values → conditional rules → origin/shop selection → cache/live quote → price cards. `providers.py::normalise_payload/_strict/_normalise_rows/_normalise_object/_normalise_map` is authoritative: hidden scalar overrides are ignored; unknown keys do not pass through; booleans and object/list values are rejected for scalar fields; blanks normalize to null. List minimum counts, blank-row handling, nested field error paths and dict defaults must remain exact. Required checks apply to explicitly submitted visible values; omitted values can retain defaults and bypass those checks. Do not silently replace this with blanket “all required keys must exist” logic.

Rules support eq/neq/in/gt/gte/lt/lte/between. A rule without a then target requires its if condition for all present values; with a then target, any matching if value triggers the then check. Empty if values skip evaluation. Rules run on normalized service-unit payloads before origin selectors are removed (`providers.py::check_rules`).

Origin selectors are `origin_province_id`/`origin_city_id`. Resolve exact province+city shop first, otherwise first shop in the province; no province may use provider default shop; origin-disabled behavior follows `resolve_origin_shop`. Remove origin selectors from outbound JSON while preserving internal mapping metadata. Shop IDs are canonical strings, not locator point/provider IDs. `provider_calls.py::build_request` uses passthrough adapters for post/irpost/tipax (and fallback); when applicable it loads the selected shop token server-side into Authorization. Do not return or log that header.

**Bulk quote:** `records.py::normalise_bulk_config` stores provider IDs, shared fields, sources/mirrors, per-provider target mappings, `value_mappings`, variants, location, price and weight. `api.py::_bulk_incoming` applies shared-unit conversion, mirror precedence, source-owner routing and explicit mappings; option-value translations use string keys and unmapped values pass through. Nested list targets populate the first row; dict targets populate an object. Normalize each provider payload independently. Cartesian variant combinations override targets. Destination coverage is checked before live calls. Preflight maps provider errors back to shared fields and excludes coverage checking. The check endpoint also validates, but preflight is a separate frontend step. `asyncio.gather` runs provider/variant calls concurrently and preserves job result order; one provider's expected error does not cancel others.

**Units:** `providers.py::convert_currency_amount` leaves equal-unit/non-number values unchanged; rial→toman divides by 10 and rounds half-up away from zero; toman→rial multiplies by 10, preserving int/float distinctions. Numeric strings are parsed only when converting. Weight uses 1,000 grams/kg, no rounding when dividing, and integral quotients become integers. Money/weight kinds or designated `param[.sub]` targets convert display→service in normalization; carrier prices convert service→display; weight has no response conversion. Bulk first converts shared units→provider display units, then normalization converts to service units. Avoid double conversion and preserve the exact treatment of defaults/omitted values, not just the comments describing them.

**Carrier result:** `provider_calls.py::parse_response/extract_prices/evaluate_prices/_mark_main_price` looks up full dotted paths including list indices. With no configured paths, it uses known send_price/just_send_price/tax/total paths or list value/price/amount/total fallbacks. Numeric matching, not HTTP or carrier status alone, decides price success; partial matches succeed and carry internal unmatched paths. Missing all prices raises 502; public error hides carrier internals. Main flags match configured labels (including duplicate-label effects), otherwise first-row fallback when no main label resolves. Referral is public only when enabled with title and valid HTTP(S) URL.

## Cache, locations, logs and abuse handling

`api.py::_cache_key/_quote_with_cache`, `storage.py::get_price_cache/save_price_cache/price_cache_is_fresh`: SHA-256 of Python sorted JSON material containing normalized params, price fields, currency pair and weight pair, keyed with provider ID. Endpoint deliberately excluded. Fresh window defaults 24h; retention defaults 10 days; prune on reads/writes. Timeout status 504 alone permits retained stale fallback; other errors do not. Cache read/write failures are best-effort. Store prices without main flags; resolve current main settings on every cache hit. Reproducing Python JSON whitespace, escaping and numeric formatting needs fixtures if retaining hash compatibility. Stored JSON is truncated at 20,000 characters, even for cached quote data; do not assume arbitrary-size cache records round-trip safely.

`locations.py`: POST global city reference with a stored shop's credentials, own shop first then another usable configured shop. Provider availability aliases are matched; city/province codes and labels stay separate. Source/custom-only/custom-merge lists, blocked locations, combined/separate origin and destination controls, pairing and merged bulk bindings must persist; in merges service title/grouping wins code conflicts (`records.py::_location_custom_mode`). Location cache is process-local with a lock: 6h fresh by default, validated stale entries usable indefinitely on refresh/credential failure, replaced only on successful refresh. Public schema tolerates unavailable reference data and manual options; direct lookup may return 503. Port needs durable last-valid snapshot storage plus refresh locking; an expiring transient alone would lose permanent stale fallback. Startup background warm-up needs a WordPress lifecycle/cron equivalent, not a long activation network call.

`storage.py::save_quote_log/list_quote_logs`: only failed live calls stored, newest first, prune at read/write, default 7-day retention. Truncate payload/response JSON to 20,000 characters plus marker; parser may return truncated strings. Logs record provider ID/name/title, endpoint, error, payload and available raw response. `_log_quote` is best-effort; the separate Authorization header is not included, but `_log_params` copies normalized params without general secret redaction. Do not assume arbitrary configured defaults or carrier responses are safe to log. Preview quotation calls bypass price cache and quote logs; schema/reference loading can still read/write location state. Security events default to 30-day retention; cache settings editable in seconds with 1–30-day bounds. Manual clears must affect only this module.

`security/config.py`, `security/pipeline.py`, `security/infra_starlette.py`, `security/rate_limiter.py`, `security/canonical.py`, `security/fingerprint.py`: guard before quote cache; trusted-proxy IP resolution; random 128-bit `tapin_cid` cookie (HttpOnly, SameSite=Lax, one year); browser/client/request fingerprints with deterministic canonicalization; block IP, client ID, fingerprint; fixed-window counters per route and present dimensions (IP, client ID, fingerprint, IP+client). Catalog defaults: metadata GETs 60/minute, quotes 4/minute, bulk preflight 30/minute; route overrides win, disabled override is unlimited. Health is unguarded. Allowlisted IPs skip blocks/rate enforcement but still face size checks. Store/event failures are generally best-effort/fail-open in the source; document deliberate changes before tightening behavior.

Deny envelope is `{success:false,code,message,detail,retry_after}` with 403 blocked, 429 limited (Retry-After header), or 413 oversized; public body cap is 256 KiB. Fingerprinting accepts optional `client` browser signals; missing/malformed data is handled rather than treated as authentication. Limits remain independent of WordPress admin authorization. Map new REST paths to the same catalog identities so ID variations share a budget.

## Stage 6 single-quote request and transport

`ProviderRequestBuilder` ports `provider_calls.py::normalize_endpoint/normalize_shop_id/build_request`: endpoint validation precedes payload copying/shop lookup, the three named adapters and unknown-name fallback all preserve the normalized JSON body, and the stored shop value goes directly into Authorization without an added Bearer prefix. `WordPressProviderTransport` uses `wp_remote_request` behind `ProviderTransport`, with explicit UTF-8 Python-style finite JSON, POST, Content-Type/Accept, source User-Agent, HTTP/1.1, TLS verification and identity encoding (urllib's implicit Accept-Encoding). Destination allowlisting/SSRF policy remains a prerequisite before exposing public quote routes; no public route exists in Stage 6. Automatic redirects are disabled; common urllib semantics are explicit: POST 301/302/303 becomes GET without content headers/body, POST 307/308 is returned as an HTTP error body, GET follows those five codes, same-origin authorization survives, and repeated/unique destinations are bounded by 4/10.
