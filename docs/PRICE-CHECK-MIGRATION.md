## Source HTTP contract

`app.py::routes` serves GET HTML: `/`, `/bulk`, `/advanced` use `static/index.html`; `/preview/provider` and `/preview/bulk` use that same HTML; `/admin[/]`, `/admin/providers[/new|/{provider_id}]`, `/admin/shops`, `/admin/bulk`, `/admin/logs`, `/admin/cache`, `/admin/security` use `static/admin.html`. Static assets are under `/static`; `/favicon.ico` serves the mark. Unknown `/api/` paths return 404 JSON; other unknown paths serve `static/404.html` (`not_found_page`). Framework HTTP exceptions other than 404 return plain text, including method errors. GET routes also have Starlette's implicit HEAD behavior.

All API paths below are under `/api`. Successful JSON responses default to 200 unless indicated. Ordinary errors use `{detail, errors:[{field,message}], ...extra}` (`api.py::ApiError/json_error`); unexpected exceptions produce 500 `{detail:"internal error"}`. Preserve Persian messages and field paths. Do not expose WordPress's native error shape to the existing JS without an adapter. `_body` accepts empty body as `{}`, rejects malformed JSON or non-object JSON with 400. Unknown/inactive public providers return 404. IDs or technical names resolve through `providers.get_provider`; location lookup additionally accepts display titles case-insensitively.

## Calculation and flow preservation

**Provider configuration:** `records.py::normalise/_params/_fields/_rules/_location_config/normalise_bulk_config` and `providers.py::_build_record`. Stable provider/param/field IDs, names, ordering, visibility, defaults, active state, endpoint, shop ID, logo, timeout, price paths/main key, referral, unit settings, rules and location configuration are functional data. Inputs: text/number/select/list/dict/map; value types str/int/float; kind city/province/money/weight. Validate duplicate names, invalid target references and map output-key collisions. Preserve options and nested row fields. Timeout defaults to 15 seconds; configured bounds are 1–300 seconds (`records.py::_timeout`). Save owned row IDs in place; foreign/duplicate IDs become new rows (`storage.py::save_provider`), preserving ID-based bulk references through rename.

**Single quote:** load active list → schema/reference bindings → collect dynamic form → parse request and run abuse guard → resolve active provider → normalize defaults and typed values → conditional rules → origin/shop selection → cache/live quote → price cards. `providers.py::normalise_payload/_strict/_normalise_rows/_normalise_object/_normalise_map` is authoritative: hidden scalar overrides are ignored; unknown keys do not pass through; booleans and object/list values are rejected for scalar fields; blanks normalize to null. List minimum counts, blank-row handling, nested field error paths and dict defaults must remain exact. Required checks apply to explicitly submitted visible values; omitted values can retain defaults and bypass those checks. Do not silently replace this with blanket “all required keys must exist” logic.

Rules support eq/neq/in/gt/gte/lt/lte/between. A rule without a then target requires its if condition for all present values; with a then target, any matching if value triggers the then check. Empty if values skip evaluation. Rules run on normalized service-unit payloads before origin selectors are removed (`providers.py::check_rules`).

Origin selectors are `origin_province_id`/`origin_city_id`. Resolve exact province+city shop first, otherwise first shop in the province; no province may use provider default shop; origin-disabled behavior follows `resolve_origin_shop`. Remove origin selectors from outbound JSON while preserving internal mapping metadata. Shop IDs are canonical strings, not locator point/provider IDs. `provider_calls.py::build_request` uses passthrough adapters for post/irpost/tipax (and fallback); when applicable it loads the selected shop token server-side into Authorization. Do not return or log that header.

**Bulk quote:** `records.py::normalise_bulk_config` stores provider IDs, shared fields, sources/mirrors, per-provider target mappings, `value_mappings`, variants, location, price and weight. `api.py::_bulk_incoming` applies shared-unit conversion, mirror precedence, source-owner routing and explicit mappings; option-value translations use string keys and unmapped values pass through. Nested list targets populate the first row; dict targets populate an object. Normalize each provider payload independently. Cartesian variant combinations override targets. Destination coverage is checked before live calls. Preflight maps provider errors back to shared fields and excludes coverage checking. The check endpoint also validates, but preflight is a separate frontend step. `asyncio.gather` runs provider/variant calls concurrently and preserves job result order; one provider's expected error does not cancel others.

**Units:** `providers.py::convert_currency_amount` leaves equal-unit/non-number values unchanged; rial→toman divides by 10 and rounds half-up away from zero; toman→rial multiplies by 10, preserving int/float distinctions. Numeric strings are parsed only when converting. Weight uses 1,000 grams/kg, no rounding when dividing, and integral quotients become integers. Money/weight kinds or designated `param[.sub]` targets convert display→service in normalization; carrier prices convert service→display; weight has no response conversion. Bulk first converts shared units→provider display units, then normalization converts to service units. Avoid double conversion and preserve the exact treatment of defaults/omitted values, not just the comments describing them.

**Carrier result:** `provider_calls.py::parse_response/extract_prices/evaluate_prices/_mark_main_price` looks up full dotted paths including list indices. With no configured paths, it uses known send_price/just_send_price/tax/total paths or list value/price/amount/total fallbacks. Numeric matching, not HTTP or carrier status alone, decides price success; partial matches succeed and carry internal unmatched paths. Missing all prices raises 502; public error hides carrier internals. Main flags match configured labels (including duplicate-label effects), otherwise first-row fallback when no main label resolves. Referral is public only when enabled with title and valid HTTP(S) URL.

## Cache, locations, logs and abuse handling

`api.py::_cache_key/_quote_with_cache`, `storage.py::get_price_cache/save_price_cache/price_cache_is_fresh`: SHA-256 of Python sorted JSON material containing normalized params, price fields, currency pair and weight pair, keyed with provider ID. Endpoint deliberately excluded. Fresh window defaults 24h; retention defaults 10 days; prune on reads/writes. Timeout status 504 alone permits retained stale fallback; other errors do not. Cache read/write failures are best-effort. Store prices without main flags; resolve current main settings on every cache hit. Reproducing Python JSON whitespace, escaping and numeric formatting needs fixtures if retaining hash compatibility. Stored JSON is truncated at 20,000 characters, even for cached quote data; do not assume arbitrary-size cache records round-trip safely.

`locations.py`: POST global city reference with a stored shop's credentials, own shop first then another usable configured shop. Provider availability aliases are matched; city/province codes and labels stay separate. Source/custom-only/custom-merge lists, blocked locations, combined/separate origin and destination controls, pairing and merged bulk bindings must persist; in merges service title/grouping wins code conflicts (`records.py::_location_custom_mode`). Location cache is process-local with a lock: 6h fresh by default, validated stale entries usable indefinitely on refresh/credential failure, replaced only on successful refresh. Public schema tolerates unavailable reference data and manual options; direct lookup may return 503. Port needs durable last-valid snapshot storage plus refresh locking; an expiring transient alone would lose permanent stale fallback. Startup background warm-up needs a WordPress lifecycle/cron equivalent, not a long activation network call.

`storage.py::save_quote_log/list_quote_logs`: only failed live calls stored, newest first, prune at read/write, default 7-day retention. Truncate payload/response JSON to 20,000 characters plus marker; parser may return truncated strings. Logs record provider ID/name/title, endpoint, error, payload and available raw response. `_log_quote` is best-effort; the separate Authorization header is not included, but `_log_params` copies normalized params without general secret redaction. Do not assume arbitrary configured defaults or carrier responses are safe to log. Preview quotation calls bypass price cache and quote logs; schema/reference loading can still read/write location state. Security events default to 30-day retention; cache settings editable in seconds with 1–30-day bounds. Manual clears must affect only this module.

`security/config.py`, `security/pipeline.py`, `security/infra_starlette.py`, `security/rate_limiter.py`, `security/canonical.py`, `security/fingerprint.py`: guard before quote cache; trusted-proxy IP resolution; random 128-bit `tapin_cid` cookie (HttpOnly, SameSite=Lax, one year); browser/client/request fingerprints with deterministic canonicalization; block IP, client ID, fingerprint; fixed-window counters per route and present dimensions (IP, client ID, fingerprint, IP+client). Catalog defaults: metadata GETs 60/minute, quotes 4/minute, bulk preflight 30/minute; route overrides win, disabled override is unlimited. Health is unguarded. Allowlisted IPs skip blocks/rate enforcement but still face size checks. Store/event failures are generally best-effort/fail-open in the source; document deliberate changes before tightening behavior.

Deny envelope is `{success:false,code,message,detail,retry_after}` with 403 blocked, 429 limited (Retry-After header), or 413 oversized; public body cap is 256 KiB. Fingerprinting accepts optional `client` browser signals; missing/malformed data is handled rather than treated as authentication. Limits remain independent of WordPress admin authorization. Map new REST paths to the same catalog identities so ID variations share a budget.

## Stage 3 confirmed pure-rule contract and compatibility limits

The isolated PHP API now covers `records.py::normalise` (`ProviderConfig::normalise`), `normalise_bulk_config/bulk_active_providers/bulk_mappings_for` (`BulkConfig`), and the provider reference/default, payload, conditional-rule and unit helpers (`ProviderDefinition`, `PayloadNormalizer`, `Units`). Classes remain under `src/PriceCheck/`; no new hooks, storage adapter, HTTP transport, endpoint or UI is connected. Storage-row decoding (`providers.py::_build_record/_build_param/_build_field`), bulk quote orchestration in `api.py`, price extraction and cache behavior remain later work. Configuration timeout normalization preserves null for omission/blank (`records.py::_timeout`); applying the request-time default belongs to the later transport stage.

Newly confirmed source details, exercised with synthetic inputs:

- Python truthiness treats the string `"0"` as true. Boolean provider IDs and positive boolean `min_items` survive normalization, while boolean param/field IDs become null (`records.py::normalise/_params/_row_id`). Nested required errors use unindexed `param.sub` paths while type errors include list indices (`providers.py::_normalise_rows`). Omitted required scalars retain their defaults without blanket required checking or scalar unit conversion; hidden and nested defaults follow their separate conversion paths. Scalar select submissions undergo type/required validation, without enforcing option membership; string values retain their whitespace (`providers.py::_strict/normalise_payload`).
- `records.py::normalise_bulk_config` accepts leading underscores in field names despite its error text. Its legacy-name mapping fallback is reached only when the ID-keyed row is explicitly null: an absent ID row becomes an empty mapping first. Preserve that behavior. Source/mirror references exclude list/dict targets but allow map targets; variants impose separate target constraints and are validated only after earlier sections succeed. Provider selection iterates strings and mapping keys; non-iterable nonempty values raise `TypeError`, not a newly invented record-validation error. No provider fan-out or incoming bulk-payload assembly is implemented here.
- URL validation uses `urlsplit().hostname` without inspecting `.port`; nonnumeric and out-of-range ports are accepted in the source. PHP validation preserves these tested cases, rather than tightening them with `parse_url`. This is configuration validation, not authorization to make a request; the later WordPress HTTP boundary still needs the policy described above.
- Python accepts NaN/infinity numeric strings in float coercion and numeric rule definitions, but timeout validation rejects them. Weight division preserves non-finite floats; currency rounding to an integer can raise a source exception. Preserve the pure results rather than invent finite-value validation. Non-finite JSON transport remains unresolved: these tests encode special fixture markers, not a successful public JSON response.
- Direct `int`/`float` constructors reject U+001c..001f around nonblank text, although Python `str.strip()` removes these characters. Preserve that distinction between raw coercion/row IDs/timeouts and conversions/strict payload fields that strip first. Unit parsing uses case-folding; the Kelvin sign in `Kg`, `KILO` and `Kilogram` resolves to kilogram.

Use JSON objects as `stdClass` (or associative arrays) and lists as indexed PHP arrays; specifically `{}` is `new stdClass`, while `[]` is an empty array. Outputs preserve objects, lists, key order and scalar types. `NormalizedPayload` carries separate origin metadata and serializes only its `values`. `PayloadNormalizer::normalise(provider, incoming, shops)` requires explicit, already-loaded shop records, including an explicit empty list. It implements selection against that supplied data; it cannot emulate storage lookup failures. Never supply shop credentials to this pure API.

PHP compatibility remains bounded and must be resolved before claiming general parity:

- Python arbitrary-precision integers and integer conversion/multiplication beyond `PHP_INT_MIN..PHP_INT_MAX` cannot be represented faithfully by native PHP integers. The port raises `DomainException` rather than truncating, wrapping, converting to a lossy float or reporting a fabricated business-validation error. Supplementary Unicode decimal-digit blocks outside the implemented BMP digit table also raise this explicit compatibility error. Five separately recorded Python executions demonstrate these limits; the PHP guard tests are **not parity successes**.
- Python `str.isdigit()` includes non-decimal digits beyond PHP's current `\p{Nd}` check. That reference-resolution edge is not confirmed equivalent. Exotic URL authorities (Unicode NFKC rejection, IPv6 zone identifiers and malformed bracket combinations) also need a full `urlsplit` compatibility decision. No quote endpoint currently exposes these helpers.
- Float-to-text compatibility is tested for signed zero, exponent transitions, coordinates and selected precision boundaries with PHP `serialize_precision=-1`. Exhaustive decimal ties, alternative PHP precision settings, Unicode-version differences between Python/PCRE, invalid UTF-8 and non-JSON Python objects are unverified. Payload JSON tests compare decoded structure/types and origin exclusion; they do not establish byte-identical JSON encoding or cache-hash compatibility.

## Stage 4 configuration persistence findings

`ProviderStorage` ports `storage.py::list_providers/get_provider_row/get_provider_id_by_name/get_param_rows/get_field_rows/next_provider_id/save_provider/delete_provider`; `load/all` reconstruct the stored configuration through `providers.py::_build_record/_build_param/_build_field` and their lenient JSON/location readers (`StoredProvider`). These readers intentionally differ from strict draft validation: scalar defaults are stored as Python text and coerced by their declared type on load; empty defaults become SQL null, list/dict defaults stay null, default rial/gram units are stored as null, empty options/rules/price paths become null, and options keys can be absent on load. Returned shapes follow the source load path, rather than pretending every submitted scalar type survives storage unchanged.

Provider/param/field IDs and positions retain the source ownership rules. Only an existing, unused ID owned by the provider (or the specific parent param for a field) is updated; missing, foreign and duplicated IDs allocate new rows. Missing nested rows are deleted and Stage 2 foreign keys cascade. Provider IDs use `MAX(id)+1`, or an explicit supplied ID; no new ID allocator or seed is introduced. Provider `shop_id` is a logical varchar reference, not a join to locator providers/service points. Provider deletion and bulk-reference pruning are separate source operations (`storage.py::delete_provider/prune_bulk_provider`, called consecutively by `api.py::admin_delete_provider`). Existing price-cache rows may cascade through the Stage 2 FK on deletion; this does not add cache persistence.

Confirmed correction to transaction assumptions: `db.py::_pool` sets `autocommit=True`. Its `_Connection.__exit__` calls commit/rollback, but configuration writes are already committed statement by statement. The port therefore starts no transaction and preserves partial writes when a later nested write fails. It neither commits nor rolls back an externally owned WordPress transaction. Atomic configuration saves would be a deliberate future behavior change. Concurrent `MAX(id)+1` allocation remains capable of a duplicate-key failure; the port reports that failure instead of claiming success or silently retrying with another ID.

`storage.py::save_provider` attempts INSERT when its provider UPDATE reports zero affected rows. MySQL's default changed-row semantics can return zero for an unchanged existing provider; that fallback then fails on its primary key. The port preserves this source quirk. Child-row unchanged updates, missing deletes and empty field-ID queries remain successful/no-op as applicable. Every wpdb operation checks both its return value and `last_error`; `StorageError` exposes a fixed message and operation name without SQL, submitted configuration or database error details. Database error display is suppressed only for the operation and restored afterwards.

Configuration JSON uses Python-style Unicode, spaces, float text and object/list distinction (`ConfigurationJson`). This concerns persisted configuration, not quote-cache hashes. Non-finite JSON/database numbers raise explicit compatibility exceptions rather than being encoded as null or discarded; source Python JSON accepts NaN/infinity, so this remains a documented unresolved representation difference. Stage 3 large-integer, Unicode and precision limitations still apply. No schema, schema version, authentication boundary or frontend behavior is changed.

`tests/price-check-storage-python.py` executes the original storage/provider functions against a disposable SQLite memory connection, replaces the original `db` module before import, supplies empty/default environment doubles, and never calls init/seeding. Its SQL double adapts MySQL upserts and changed-row counts; SHA-256 hashes pin source provenance. `tests/price-check-storage.php` uses a wpdb-shaped PDO SQLite double derived from the unchanged Stage 2 column declarations, with cascade constraints and injected failures. It could not run here because that environment is absent. No live database or credentials were used.

`ShopStorage` ports `storage.py::clean_shop_row/list_shops/get_shop/save_shops/delete_shop`. The whole batch is cleaned before the first write; an invalid later row leaves every row unwritten. Subsequent SQL failures retain source autocommit behavior. IDs stay varchar: integer/whole-float save IDs canonicalize to integer text, string IDs preserve leading zeros, and lookups use their own direct string conversion. Listing sorts by string ID, returns integer `has_token` and omits the private column; untrimmed nonempty province/city filters are passed through as in Python. `BulkStorage` ports `storage.py::empty_bulk_config/get_bulk_config/save_bulk_config/prune_bulk_provider`. The singleton is ID 1; absent, malformed or non-object finite JSON reads return the source's empty configuration, which has no `weight` or `value_mappings` key. A saved `{}` remains `{}`. Saves replace the whole JSON object, including unknown keys, ordered arrays, null/default values and integer/float distinctions. Pruning removes matching numeric and legacy-name provider selections and mapping/value-mapping/variant keys, nulls source/mirror slots, preserves unrelated references, and writes only when changed. Global cache/security settings and route-limit storage are independent helpers in `storage.py`; provider/shop/bulk saves do not call them.
